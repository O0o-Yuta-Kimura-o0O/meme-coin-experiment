# 税務申告用の取引記録（メンバーごとの CSV）

ブロックチェーン上の出来事のうち、税務で必要になりそうなものを、**メンバーごと**に、**その時点の円換算額つき**で CSV に記録し続けます。どれが課税対象になり、いつ所得になるかの判断は税理士に任せ、この記録はその材料をもれなく残すことを目的にしています。

## 個人情報の扱い

- プログラム（`tax/ledger.py`）には個人情報は入っていない
- 「どのウォレットが誰のものか」を書いた設定ファイルと、出力した CSV は **`private/tax/` に置く**。`private/` は Git の対象外なので、GitHub には上がらない
- 設定ファイルのひな形：[config.example.json](config.example.json)

## 自動実行（非公開リポジトリ）

`private/tax/` は、非公開リポジトリ **`seppuku-tax-ledger`**（GitHub、永久に非公開）の手元の作業場所です。GitHub Actions が **6 時間ごと**に記録を更新してコミットします。手元で見る前に `cd private/tax && git pull` で最新にしてください。`ledger.py` を直したら、`private/tax/ledger.py` にもコピーします。

## 使い方

```bash
python3 tax/ledger.py private/tax/config.testnet.json
```

- 前回どこまで読んだかを `private/tax/<出力先>/state.json` に保存し、次回はその続きから追記する
- 実行しなかった期間があっても、次に実行したときにさかのぼって記録する（ブロックチェーンの記録は消えないため）
- ただし、ETH の円相場は 1 時間ごとの値が **直近 90 日分** しか無料で取れない。それより古いと 1 日ごとの値になる。精度を保つため、**少なくとも月に 1 回**は実行する
- 一度取得した円相場は `state.json` に保存されるので、あとから精度が落ちることはない

## CSV の列

| 列 | 内容 |
|---|---|
| `datetime_jst` / `unix_time` | 出来事が起きた日時 |
| `network` | `base`（本番）/ `base_sepolia`（テストネット。ETH に価値はなく、円換算は参考値） |
| `owner` | メンバー（設定ファイルの名前） |
| `coin` | どのコインに関する出来事か |
| `category` | 出来事の種類（下の表） |
| `asset` / `amount` | 増減した資産と数量。**プラスは受け取り、マイナスは手放した**（小数点以下 18 桁まで） |
| `unit_price_jpy` / `value_jpy` | その時点の 1 単位の円換算額 / 数量 × 単価 |
| `eth_jpy` | その時点の ETH の円相場（CoinGecko、1 時間ごと） |
| `tx_hash` / `block` | 取引の ID とブロック番号（Basescan / Blockscout で確認できる） |
| `note` | 補足 |

コインの円換算額は「プールの価格（ETH 建て）× ETH の円相場」で計算します。プールができる前（発行直後など）は 0 円です。

## 記録する出来事

| category | 内容 | 税務上の論点（税理士に確認） |
|---|---|---|
| `issuance` | コインの発行。取得価額は 0 | — |
| `vesting_lock` | 発行したコインを、半減期ロックに割り当てた | 相手のロックへの割当が、共同発行か贈与か |
| `vesting_release` | 半減期ロックから受け取った | 受け取った時点で所得になるか |
| `lp_deposit` | ウォレットから流動性プールへコインを預けた | 預けた時点で譲渡になるか |
| `lp_position_in` | 自分の LP ポジションに元本が入った | 相手のウォレットから入った分の扱い |
| `lp_swap` | 自分の LP ポジションの中で、買い手・売り手との交換によって増減した持ち分（コインが減り ETH が増える等） | 当方の所得にならない前提で扱う（2026-11-02 の方針）。時価（円）は、その時点の価値の**歴史の記録として**残す（税の計算には使わない。note に「時価は記録用」と書く） |
| `lp_fee` | 自分の LP ポジションに発生した取引手数料の持ち分 | 発生時か回収時か |
| `lp_withdraw` | LP ポジションからウォレットへ回収した。**永久ロック（`PermanentLPLock`）では手数料だけ**（元本は引き出せない） | 手数料の所得 |
| `trade` | 自分のウォレットで、このプールを使って売買した | 交換の時点で譲渡 |
| `partner_transfer` | メンバー間（コミュニティ用を含む）の受け渡し | 共有物の移動か贈与か |
| `transfer_in` / `transfer_out` | それ以外のアドレスとの受け渡し（無償配布など） | 無償配布の扱い |
| `gas_fee` | 自分が送信した取引の手数料 | 経費 |

手数料と半減期ロックの解放分は、ウォレットに入った時点（`lp_withdraw`・`vesting_release`）の時価で記録しています（ETH/円は1時間ごとの相場）。

`lp_swap` と `lp_fee` は、各ポジションの流動性 ÷ その時点の有効な流動性で按分しています（ポジションの価格帯の内側にあるときだけ）。

## 記録しないもの・注意点

- **取引所（CEX）での売買、円への換金**：ブロックチェーンの外なので記録できない。取引所が出す取引履歴を別に保管する
- **ウォレット間の ETH そのものの送金**（イベントが残らない送金）と、**失敗した取引の手数料**：記録しない（金額はごくわずか）
- **このプール以外での売買**（別の DEX やアグリゲーター経由）：`transfer_in` / `transfer_out` として残るだけで、相手側の資産は記録されない
- 1 回の取引の中で価格帯をまたいで流動性が変わる場合、按分はおおよその値になる
- 端数：数量は wei（10^-18）単位まで、円換算は 0.01 円単位。ブロックチェーン上の値と 1 wei 程度ずれることがある

## 本番用の設定

デプロイと流動性の追加が終わったら、送信記録からコインの情報を自動で書き足します（設定ファイルを手で書く必要はない）。

```bash
cp private/tax/mainnet.pending.json private/tax/config.mainnet.json
```

```bash
python3 tax/add_coin.py 8453 private/tax/config.mainnet.json SEPPUKU
```

- トークン、プール、LP ポジションの番号と手数料の受取人、半減期ロックと受取人を読み取り、`owners` のウォレットと突き合わせてメンバーに割り当てる
- 2 つ目以降のコインも同じコマンドで足せる。記録が既にそのコインのデプロイより先まで進んでいても、次の実行で、そのコインの分だけさかのぼって読む（`from_block`）。同じ記録が二重に書かれることはない
